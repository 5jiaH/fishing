# 钓点智能分析落地方案

## 1. 需求结论

当前需求整体可落地，但需要拆分为“可直接上线能力”和“需要数据/模型增强后上线能力”。

可优先上线的能力：

- 基于河流矢量数据构建河段库，识别主河流、支流、入海口、河流名称、河段上下游关系。
- 结合遥感影像提取水面范围、河宽区间、弯道、支流交汇、沙洲/滩地、岸线变化等钓点相关地形特征。
- 接入实时天气、水位、流量、潮汐数据，形成河段级钓鱼适宜性评分。
- 给出推荐原因，例如“近 24 小时水位稳定”“支流交汇”“风速适中”“降雨后浑水风险”等。

需要谨慎上线的能力：

- “河床结构”不能完全依赖公开遥感影像直接识别。光学遥感主要看到水面和浅水区，深水、水下坑洼、暗流、硬底/泥底等信息需要用水位变化、岸线变化、河宽、弯道、历史影像、水文站数据做代理推断，关键区域需要人工采样、声呐或测绘数据校验。
- “电线塔/电线经纬度”不能只依赖 Sentinel-2、Landsat 这类开源影像。10m/30m 分辨率不足以稳定识别电线塔和电线。若要生产级使用，需要亚米级或米级高分影像、外部电力设施数据、OSM 补充数据、目标检测模型和人工抽检闭环。

推荐第一版产品形态：

> 河段数据产品 + 钓点适宜性评分 + 风险提示，不承诺精准水下河床和全自动电力设施定位。

## 2. MVP 边界

第一版建议选择 1 个流域或 2-3 条目标河流作为样区，不建议直接铺全国。

MVP 输出字段：

- 河流名称
- 河段编号
- 河流等级或主支流关系
- 入海口/支流交汇/弯道/桥梁附近等空间标签
- 河宽区间
- 水面面积和岸线变化
- 河段附近地形坡度、岸坡、滩地/沙洲
- 最近天气、风速、气温、降雨、气压变化
- 最近水位、流量、涨落趋势
- 入海口区域潮汐状态
- 钓鱼适宜性评分
- 推荐原因和风险原因

不在 MVP 中强承诺：

- 精准河床三维结构
- 精确水深
- 全国范围电线塔/电线完整经纬度
- 无人工审核的钓点“必出鱼”推荐

## 3. 数据来源总览

### 3.1 基础矢量数据

#### 公开基础数据：天地图 / 全国地理信息资源目录服务系统

推荐来源：

- 全国地理信息资源目录服务系统：https://www.webmap.cn/
- 1:25万全国基础地理数据库：https://www.webmap.cn/commres.do?method=result25W

可获取内容：

- 水系面层：HYDA，湖泊、水库、双线河流等。
- 水系线层：HYDL，单线河流、沟渠、河流结构线等。
- 水系点层：HYDP，泉、井等。
- 自然地名点层：AANP，包含部分水系名、自然地名。

获取方式：

1. 注册并登录全国地理信息资源目录服务系统。
2. 进入数据下载，选择 1:25万全国基础地理数据库。
3. 按研究区或标准图幅选择数据。
4. 加入成果车并提交申请。
5. 同意用户协议、填写使用目的后下载。
6. 将下载的 Shapefile 或 GDB 数据导入 PostGIS。

优点：

- 官方来源，字段和坐标体系相对规范。
- 覆盖全国，适合做底图、河流名称、河网拓扑初始数据。
- 获取成本低。

限制：

- 1:25万比例尺偏粗，不适合直接做精细钓点定位。
- 整体现势性偏旧，公开资料显示 1:25万公众版整体约为 2015 年。
- 公开版经过地图保密处理，位置精度和部分属性可能被降精度或脱敏。
- 公开展示地图产品时需要遵守地图管理和审图要求。

使用建议：

- 只把它作为“河网骨架”和“河流名称/上下游关系”的初始底图。
- 不要把 1:25万线位直接当作精确河岸线。
- 河道几何边界应使用遥感影像重新提取和更新。

#### 开源主数据：OSM 原始数据

如果当前阶段主要目标是“获取河流路径和河流名称”，OSM 原始数据比地图瓦片更适合作为批量数据源。

推荐来源：

- Geofabrik 中国区 OSM PBF：https://download.geofabrik.de/asia/china.html
- OSM Planet 全量数据：https://planet.openstreetmap.org/
- OSM Overpass API：适合小范围查询，不适合全国级重批量任务。

建议优先下载：

- `china-latest.osm.pbf`
- 后续通过 Geofabrik daily diff 或定期重新下载更新。

重点标签：

- `waterway=river`：河流。
- `waterway=stream`：溪流、小河。
- `waterway=canal`：运河、人工渠。
- `waterway=ditch`：沟渠。
- `waterway=drain`：排水渠。
- `natural=water`：水面面要素。
- `water=river`：河流水面。
- `water=reservoir`：水库。
- `name=*`：名称。
- `name:zh=*`、`name:en=*`：多语言名称。
- `intermittent=yes`：季节性水流。
- `tunnel=*`、`culvert=*`：涵洞或地下段。

获取方式：

1. 从 Geofabrik 下载中国区 `.osm.pbf`。
2. 用 `osm2pgsql`、`imposm`、`ogr2ogr` 或 `osmium` 过滤水系相关对象。
3. 导入 PostGIS，保留 OSM id、几何、标签、更新时间、数据来源。
4. 抽取线要素作为河道路径候选。
5. 抽取面要素作为水面候选。
6. 对线面要素做空间匹配，补全线和水面之间的关系。
7. 将 OSM 名称作为河名候选，而不是直接作为唯一权威名称。

优点：

- 可以合法批量获取原始数据，不需要抓瓦片。
- 河流路径和名称已经结构化，适合直接进入 GIS 处理。
- 覆盖小河流、沟渠、人工渠的概率高于 1:25万公开水系数据。
- 每天有更新，现势性优于很多静态公开数据。

限制：

- OSM 在中国不同区域覆盖质量差异较大。
- 小河流名称缺失、线段断裂、方向错误、重复线段都可能存在。
- OSM 采用 ODbL 协议，使用和派生数据库需要满足署名和共享协议要求。
- 不能把 OSM 官方地图瓦片当成批量下载数据源。

使用建议：

- MVP 阶段可以把 OSM 原始数据作为“河流路径和名称候选”的主数据源。
- 天地图 1:25万数据作为官方水系对照。
- 天地图瓦片作为在线底图和人工校验参考。
- 遥感影像作为河道现势性和几何纠偏来源。

### 3.2 更高精度矢量数据获取方式

由于 1:25万数据偏旧、精度较低，生产环境建议采用分级策略获取更高精度矢量。

#### 方案 A：申请官方更高比例尺基础测绘成果

可能来源：

- 全国地理信息资源目录服务系统中的 1:5万、1:1万、1:5000 等基础地理信息数据目录。
- 自然资源部政务服务门户。
- 国家基础地理信息中心服务指南。
- 省、市自然资源主管部门或测绘地理信息主管部门。

适用数据：

- 1:5万基础地理信息数据。
- 1:1万基础地理信息数据。
- 1:5000 或更高精度地形图、影像图和数字化产品。
- 地理国情监测数据。
- 地表覆盖、地名、水系、交通、居民地等专题数据。

获取方式：

1. 明确项目范围、合法用途、数据比例尺、数据类型和使用期限。
2. 查询全国地理信息资源目录服务系统是否存在对应区域和比例尺目录。
3. 若为非公开或涉密测绘成果，按属地向省级或市县自然资源主管部门提交申请。
4. 提交《基础测绘成果使用申请表》、单位证明、项目证明、保密承诺等材料。
5. 审批通过后签订使用许可协议，按授权范围使用。

优点：

- 权威性最高。
- 河流、水系、地形、地名等属性更完整。
- 适合政府、科研、工程类项目。

限制：

- 申请周期较长。
- 可能需要单位资质、明确项目用途和保密管理能力。
- 高精度数据可能不能直接用于公开互联网产品。
- 数据使用范围、展示方式、坐标精度可能受协议限制。

落地建议：

- 如果项目要做严肃商业化和长期全国数据产品，应尽早走官方申请路径。
- MVP 阶段不依赖该路径阻塞上线，先用公开数据和遥感提取跑通流程。

#### 方案 B：从高分辨率遥感影像反提取最新河道矢量

数据来源：

- Sentinel-2：10m，免费，适合中大型河流。
- Sentinel-1 SAR：10m，免费，适合多云、多雨场景下提取水体。
- Landsat 8/9：30m，免费，适合历史变化分析。
- 高分二号 GF-2：全色约 0.8m，多光谱约 3.2m，可通过中国资源卫星应用中心数据服务平台检索申请。
- 吉林一号、Superview 高景、北京二号、资源三号等国产商业/准商业影像。
- PlanetScope：约 3-5m，重访高，适合变化监测。
- SkySat：约 0.5m，适合识别细小地物。
- Maxar WorldView/GeoEye：约 0.3-0.5m，适合精细识别和矢量化。

处理方式：

1. 以公开河流矢量为初始中心线。
2. 对每条河段生成缓冲区。
3. 在 GEE 或本地遥感平台裁切影像。
4. 使用 MNDWI、NDWI、AWEI、SAR 阈值或分割模型提取水体。
5. 对水体 mask 做形态学清理、连通域过滤、云阴影剔除。
6. 矢量化水体边界，提取中心线、河宽、河岸线、沙洲、滩地。
7. 与原始水系矢量匹配，生成“更新后的河道几何”。
8. 对低置信度河段进行人工审核。

优点：

- 现势性好，可以按月、季度更新。
- 不依赖官方高精数据审批。
- 能补齐 1:25万数据的几何偏差。

限制：

- 免费 10m 影像仍不适合很窄河道。
- 光学影像受云、阴影、浑水、植被遮挡影响。
- SAR 影像有斑点噪声，城市、桥梁、湿地场景容易误判。
- 需要建立质检和人工抽检流程。

落地建议：

- MVP 使用 Sentinel-2 + Sentinel-1 + 1:25万矢量即可。
- 如果要把定位精度提升到钓点级别，重点区域采购 0.5m-3m 高分影像重新矢量化。
- 对高价值钓点、人流集中区域、入海口、桥梁周边做人工审核。

#### 方案 C：采购商业地图或行业专题矢量数据

可能来源：

- 高德、百度、腾讯位置服务等地图服务商的企业级数据服务。
- 四维图新、易图通等地图数据商。
- 遥感/GIS 数据供应商。
- 水利、环保、河湖管理相关第三方数据服务商。

可能获取内容：

- 更细水系线面。
- POI、桥梁、道路、行政区、禁钓区、危险区域。
- 河湖管理范围、岸线、排污口、码头、闸坝、水库等专题数据。

优点：

- 商业接入速度快。
- 数据维护频率可能高于公开基础数据。
- 可补充道路、桥梁、停车点、入口等钓鱼产品需要的场景数据。

限制：

- 原始矢量数据通常需要单独授权，不等同于普通地图 API 调用。
- 成本较高。
- 数据再加工、缓存、公开展示、离线使用都有授权限制。
- 水系专题精度不一定高于官方测绘数据，需要样区验证。

落地建议：

- 用商业地图数据补充道路、桥梁、POI、用户到达路线。
- 河道几何仍建议由官方数据 + 遥感提取 + 人工审核生成。

#### 方案 D：自采测绘和众包校验

适用场景：

- 核心商业钓场。
- 重点河段。
- 用户高频访问区域。
- 需要真实水深、河床、障碍物信息的区域。

可选方式：

- 无人机航测生成正射影像和高精度河岸线。
- RTK/GNSS 采集钓位、岸线、障碍物、入水口。
- 声呐/探鱼器采集水深和河床起伏。
- 用户 App 上传钓点、鱼获、水深、障碍物、禁钓提醒。
- 人工审核和置信度评分。

优点：

- 精度最高。
- 可以获得公开遥感无法获取的水下信息。
- 可沉淀差异化数据壁垒。

限制：

- 成本高，不适合一次性全国铺开。
- 需要外业流程和数据质量规范。
- 需要处理用户隐私、钓点保护和合规问题。

落地建议：

- 只对高价值样区自采。
- 将自采数据用于校准模型和验证评分规则。

### 3.3 地图瓦片的使用边界

地图瓦片可以用于识别和校验河流走向，但不建议作为核心可沉淀数据源。

#### OSM 瓦片

结论：

- OSM 原始数据可以批量下载。
- OSM 官方瓦片不允许批量抓取、预下载、离线缓存或大范围扫描。

可做：

- 前端在线展示。
- 人工审核时作为地图底图。
- 小范围交互式查看。

不可做：

- 批量抓取 `tile.openstreetmap.org` 瓦片。
- 把瓦片下载成离线库。
- 用脚本遍历 zoom/x/y 提取河流路径。
- 用无头浏览器模拟浏览器拖图批量触发瓦片加载。

正确替代方案：

- 下载 OSM PBF 原始数据。
- 自建 OSM 瓦片服务。
- 使用明确允许批量下载或离线使用的商业瓦片服务。

#### 天地图瓦片

结论：

- 天地图瓦片适合授权在线展示和人工校验。
- 不建议把天地图瓦片作为批量提取河流路径的主数据源。

可做：

- 在前端或后台使用天地图作为底图。
- 在人工审核页面叠加 OSM 河流、遥感水体和天地图底图。
- 用天地图注记辅助判断河名。
- 用少量交互式瓦片查看河流走向。

不建议做：

- 大范围批量下载瓦片。
- 绕过配额或多 Key 轮换抓取瓦片。
- 离线缓存天地图瓦片作为自有底图。
- 从瓦片图片中反向批量提取河流矢量。

原因：

- 瓦片是渲染结果，不是原始 GIS 数据。
- 河流线条经过制图综合，不等于真实河道中心线或河岸线。
- 不同 zoom 显示内容不同，小河流可能在低级别缺失。
- 瓦片没有完整属性，不能稳定获得河流 id、上下游关系和名称。
- 批量抓取可能触发限流、封禁和授权风险。

项目中的定位：

- OSM PBF：主路径和名称候选来源。
- 天地图 1:25万：官方水系对照来源。
- 天地图瓦片：人工校验和展示底图。
- 遥感影像：现势性纠偏和河段结构分析来源。

## 4. 遥感影像数据来源

### 4.1 免费开源影像

#### Sentinel-2 L2A

来源：

- Google Earth Engine：`COPERNICUS/S2_SR_HARMONIZED`
- Copernicus Browser：https://browser.dataspace.copernicus.eu/

特点：

- 空间分辨率：10m/20m/60m，常用可见光、近红外为 10m，短波红外为 20m。
- 重访周期约 5 天。
- 适合水体提取、河宽估计、中大型河流岸线变化。

使用方式：

- 过滤 AOI、日期、云量。
- 做云掩膜。
- 计算 MNDWI：`(Green - SWIR) / (Green + SWIR)`。
- 根据阈值或分类模型生成水体 mask。

适用范围：

- 宽度大于 30m 的河流效果较好。
- 对窄河、小沟渠、电塔识别不够。

#### Sentinel-1 SAR

来源：

- Google Earth Engine：`COPERNICUS/S1_GRD`
- Copernicus Browser

特点：

- C 波段 SAR，常用 10m 分辨率。
- 不受云影响，适合雨季、云量大区域。
- 可用于水体、洪水、湿地和水面变化提取。

使用方式：

- 过滤 IW 模式、VV/VH 极化、10m 分辨率。
- 做 speckle 去噪。
- 使用阈值或机器学习分类水体。
- 与 Sentinel-2 水体结果交叉验证。

限制：

- 城市、水田、湿地、桥梁附近容易误判。
- 需要按区域调阈值。

#### Landsat 8/9

来源：

- Google Earth Engine：`LANDSAT/LC08/C02/T1_L2`、`LANDSAT/LC09/C02/T1_L2`
- USGS EarthExplorer：https://earthexplorer.usgs.gov/

特点：

- 空间分辨率 30m，历史长。
- 适合做多年尺度河道变化、枯丰水季对比。

限制：

- 分辨率较低，不适合精细钓点级定位。

### 4.2 国产高分影像

#### 高分二号 GF-2

来源：

- 中国资源卫星应用中心陆地观测卫星数据服务平台：https://data.cresda.cn/
- 地理空间数据云：https://www.gscloud.cn/

特点：

- 全色分辨率约 0.8m。
- 多光谱分辨率约 3.2m。
- 适合河岸线精细提取、桥梁/建筑/大型电塔候选识别。

获取方式：

1. 注册中国资源卫星应用中心账号。
2. 进入数据检索或光学与 SAR 卫星载荷检索。
3. 按行政区、AOI、时间、云量、卫星类型筛选。
4. 选择合适产品订购。
5. 下载 GeoTIFF 等标准产品。

限制：

- 账号权限、单位资质、数据开放程度会影响可下载范围。
- 部分数据可能需要审批或付费。
- 数据处理需要遥感经验，例如正射校正、融合、辐射校正、裁切。

### 4.3 商业高分影像

可选来源：

- Planet PlanetScope：约 3-5m，高频重访，适合变化监测。
- Planet SkySat：正射产品约 0.5m，适合精细目标识别。
- Maxar WorldView/GeoEye：约 0.3-0.5m，适合高精识别和制图。
- 国内商业卫星：吉林一号、高景一号、北京二号等。

获取方式：

- 通过平台官网、企业销售、API、影像订阅、任务拍摄获取。
- Planet 可通过 Data API、Orders API、Subscriptions API 检索和下载。
- Maxar 通常通过企业账号、销售合同或合作平台获取。

适用场景：

- 电线塔识别。
- 小河道和小型水面识别。
- 核心钓场精细矢量化。
- 人工审核底图。

限制：

- 成本较高。
- 授权限制严格。
- 影像公开展示、缓存、二次加工需要合同明确。

## 5. 电线塔/电线位置数据方案

README 中的“利用遥感图像结合大模型分析电线塔/电线位置经纬度”技术上可做，但不能作为 MVP 的强依赖。

可用数据源：

- OSM：`power=line`、`power=tower`，覆盖不完整，可做候选参考。
- 高分影像：GF-2、SkySat、Maxar、吉林一号等。
- 商业地图或行业专题数据：需要单独授权。
- 人工标注数据：对样区电塔、电线走廊做训练样本。

推荐流程：

1. 用 OSM 或人工标注生成候选训练样本。
2. 用高分影像切片。
3. 训练目标检测模型识别电塔、杆塔、输电走廊。
4. 对检测点做 NMS、空间连线和异常过滤。
5. 将检测结果标记为“风险候选”，而不是直接作为权威电力设施数据。
6. 对公开展示做降精度处理，避免展示敏感设施精确位置。

模型建议：

- 电塔识别用 YOLO、RT-DETR、Mask R-CNN、SAM 辅助标注等专用 CV 模型。
- VLM/RSCoVLM 用于解释影像、辅助质检和难例审核。
- 不建议直接让 VLM 单独输出经纬度作为最终结果。

## 6. 河床结构分析方案

河床结构需要分成“可遥感推断”和“必须实测”的两类。

可从遥感推断的特征：

- 河宽变化。
- 弯道内外侧。
- 支流交汇。
- 沙洲、浅滩、裸露滩地。
- 岸线季节变化。
- 枯水期水面边界。
- 入海口潮汐影响区。
- 河道断面宽窄变化。

需要实测或外部数据的特征：

- 精准水深。
- 水下坑洼。
- 河底材质。
- 暗流。
- 水下障碍物。
- 小尺度鱼道。

推荐实现：

1. 使用多期遥感影像提取不同水位下的水面范围。
2. 使用 DEM 计算坡度、汇流方向、岸坡。
3. 使用水文站水位和遥感拍摄日期匹配，推断不同水位下的裸露/淹没区域。
4. 对高价值区域接入声呐/探鱼器/人工采样数据。
5. 输出“河床结构置信度”，不要输出无法验证的绝对结论。

## 8. 基于 OSM + 瓦片校验 + 遥感分析的详细落地步骤

本项目建议采用以下主流程：

> OSM 原始数据批量获取河流路径和名称候选 -> 天地图/商业地图瓦片在线校验 -> 遥感影像提取水面和河岸线 -> POI/地名多源命名 -> 构建河段库 -> 接实时数据 -> 输出钓点适宜性评分。

### 8.1 第 0 步：确定样区和数据标准

目标：

- 避免一开始全国铺开导致数据量、算法误差和质检成本失控。
- 先选一个能覆盖多种河流场景的样区。

样区选择建议：

1. 选择 1 个地级市、1 个县域或 1 条主要河流流域。
2. 样区内最好同时包含主河道、支流、入海口或水库、桥梁、城市段、乡村段。
3. 样区面积建议控制在 1000-10000 平方公里。
4. 优先选择已有用户需求或钓鱼场景明确的区域。

统一数据标准：

1. 内部空间坐标建议使用 WGS84 或 CGCS2000，PostGIS 中统一 SRID。
2. 前端展示如果接国内互联网地图，需要处理 GCJ-02/BD-09 与内部坐标转换问题。
3. 所有几何对象必须记录：
   - `source`：数据来源。
   - `source_id`：源数据 id。
   - `source_time`：数据时间。
   - `source_resolution`：影像分辨率或矢量比例尺。
   - `confidence`：置信度。
   - `license_note`：授权和使用限制。

阶段产出：

- 样区边界 AOI。
- 坐标系标准。
- 数据源清单。
- 数据授权记录表。

### 8.2 第 1 步：获取 OSM 原始河流数据

目标：

- 批量获取河流路径、部分河名、小河流、沟渠和水面面要素。
- 避免抓取 OSM 官方瓦片。

操作步骤：

1. 进入 Geofabrik 中国区下载页面。
2. 下载 `china-latest.osm.pbf`。
3. 如果只做样区，可用 `osmium extract` 按 AOI 裁切 PBF，减少处理量。
4. 使用 `osmium tags-filter` 或导入后 SQL 过滤水系标签。
5. 保留以下对象：
   - `waterway=river`
   - `waterway=stream`
   - `waterway=canal`
   - `waterway=ditch`
   - `waterway=drain`
   - `natural=water`
   - `water=river`
   - `water=reservoir`
   - `water=lake`
6. 保留以下字段：
   - OSM object type：node/way/relation。
   - OSM id。
   - `name`
   - `name:zh`
   - `alt_name`
   - `waterway`
   - `natural`
   - `water`
   - `intermittent`
   - `tunnel`
   - `covered`
   - `boat`
   - `width`
   - `source`
   - 完整 tags JSON。

建议入库表：

- `raw_osm_waterway_line`：OSM 河流线。
- `raw_osm_water_polygon`：OSM 水面。
- `raw_osm_water_point`：OSM 水相关点。
- `raw_osm_name_index`：名称索引。

关键质检：

1. 删除明显无效几何。
2. 修复自相交线。
3. 将 MultiLineString 拆为单线。
4. 对重复 OSM way 做去重。
5. 标记无名称线段。
6. 标记过短线段，例如长度小于 30m 的孤立线。

阶段产出：

- OSM 水系原始库。
- OSM 河流路径候选库。
- OSM 河名候选库。

### 8.3 第 2 步：导入天地图 1:25万水系作为官方对照

目标：

- 不把 1:25万作为高精路径，而是作为官方水系、河名和主河道对照。

操作步骤：

1. 在全国地理信息资源目录服务系统下载目标图幅。
2. 解压数据，确认水系层：
   - HYDL：线水系。
   - HYDA：面水系。
   - HYDP：点水系。
   - AANP：自然地名点。
3. 统一坐标系。
4. 导入 PostGIS。
5. 将字段映射到统一 schema。
6. 与 OSM 水系做空间叠加。

匹配规则：

1. OSM 线和天地图线距离小于阈值，例如 100m-300m，视为候选匹配。
2. OSM 名称和天地图名称一致，提升名称置信度。
3. OSM 有线无名，天地图附近有同方向同河流名称，可作为名称候选。
4. 天地图有主河道但 OSM 缺失，加入“待遥感补全”队列。
5. OSM 有小河流但天地图没有，保留 OSM，但降低官方对照置信度。

阶段产出：

- 官方水系对照库。
- OSM/天地图匹配关系表。
- 名称冲突表。
- 缺失河流候选表。

### 8.4 第 3 步：使用地图瓦片做在线校验，不做批量抓取

目标：

- 利用天地图或商业地图瓦片的视觉表达，帮助人工确认河流走向、名称和缺失情况。
- 不把瓦片作为批量数据源。

后台校验页面建议图层：

1. 天地图矢量底图。
2. 天地图影像底图。
3. OSM 河流线。
4. 天地图 1:25万水系线。
5. 遥感提取水体 mask。
6. 当前河段中心线。
7. POI/地名候选点。
8. 低置信度问题点。

人工校验动作：

1. 查看 OSM 河流线是否贴近瓦片中的河流。
2. 查看河流名称是否与瓦片注记一致。
3. 标记 OSM 缺失但瓦片可见的河流。
4. 标记 OSM 存在但瓦片和遥感均不可见的线段。
5. 标记支流交汇处命名冲突。
6. 标记桥梁、闸坝、入海口、水库出入口等关键点。

系统约束：

1. 只加载用户当前视野内瓦片。
2. 遵守服务商缓存和调用限制。
3. 不做后台批量预抓。
4. 不将瓦片图片沉淀为训练数据或离线数据库，除非授权明确允许。

阶段产出：

- 人工校验记录。
- 低置信度河段修正记录。
- 缺失河流补全任务。

### 8.5 第 4 步：构建河网 graph

目标：

- 将 OSM、天地图和遥感提取结果转成可遍历的河网。
- 后续才能沿水面方向补全河段、传播河名、判断上下游。

处理步骤：

1. 将河流线统一拆分为基础 edge。
2. 在所有线段端点生成 node。
3. 对距离很近的端点做 snap，例如 5m-30m，根据数据源精度调整。
4. 对线段交叉点做 split，确保支流交汇处有节点。
5. 删除重复 edge。
6. 合并方向一致、名称一致、无交汇的连续 edge。
7. 标记每个 node 的度数：
   - 度数 1：源头、终点、断点。
   - 度数 2：普通连续点。
   - 度数大于 2：支流交汇点。
8. 对湖泊、水库、水面面要素建立入口/出口候选点。
9. 建立 `river_graph_node` 和 `river_graph_edge`。

方向推断：

1. 优先使用 OSM way 原始方向，但不能完全相信。
2. 使用 DEM 计算端点高程，高处到低处作为候选流向。
3. 入海口、水库出口、主河道下游位置作为强约束。
4. 水文站上下游关系作为辅助约束。
5. 如果流向冲突，标记为 `flow_direction_confidence=low`。

河段切分规则：

1. 每 500m-2000m 切一个基础河段，视河流大小调整。
2. 支流交汇处必须切分。
3. 桥梁、闸坝、水库入口、入海口必须切分。
4. 河宽显著变化处切分。
5. 行政区边界可以作为可选切分点。
6. 城市/乡村岸线变化明显处切分。

阶段产出：

- 河网节点表。
- 河网边表。
- 河段表。
- 上下游关系表。
- 河段切分日志。

### 8.6 第 5 步：用 POI/地名给河段命名

目标：

- 不依赖单一来源命名。
- 给每个河段分配河名，并输出名称置信度。

名称来源：

1. OSM `name`、`name:zh`、`alt_name`。
2. 天地图 AANP 自然地名点。
3. 天地图瓦片注记人工核验结果。
4. 高德/百度/腾讯 POI 或地名检索结果。
5. 地方水利、河湖名录、政府公开河长制数据。
6. 用户反馈和人工审核。

命名步骤：

1. 将所有名称点或名称线统一进入 `name_candidate` 表。
2. 对名称做清洗：
   - 去掉空格。
   - 统一繁简体。
   - 处理“河”“溪”“沟”“渠”等后缀。
   - 合并同义别名。
3. 将名称候选点投影到最近河网 edge。
4. 设定最大匹配距离：
   - 大河：可放宽到 300m-1000m。
   - 小河：建议 50m-200m。
   - 城市密集区：距离阈值要更严格。
5. 名称沿 graph 向上下游传播。
6. 遇到以下情况停止传播或降低置信度：
   - 支流交汇。
   - 名称冲突。
   - 水库/湖泊。
   - 河道断裂。
   - 距离名称来源过远。
   - 遥感水体不连续。
7. 对每个河段生成 `name_confidence`。

置信度建议：

- 0.9-1.0：OSM、官方地名、瓦片注记/人工审核一致。
- 0.7-0.9：两个来源一致，空间距离合理。
- 0.5-0.7：只有一个来源，但与河网位置吻合。
- 0.3-0.5：通过传播获得，附近有冲突。
- 0-0.3：无名称或明显冲突。

阶段产出：

- 河段名称表。
- 名称来源关系表。
- 名称置信度。
- 名称冲突待审核列表。

### 8.7 第 6 步：根据河段经纬度拉取遥感影像

目标：

- 对每个河段找到对应遥感影像，分析当前水面、河宽、滩地、岸线、交汇结构。

AOI 生成规则：

1. 对河段中心线生成 buffer。
2. buffer 宽度按河流等级调整：
   - 小河/溪流：100m-300m。
   - 普通河流：300m-1000m。
   - 大江大河：1000m-3000m。
   - 入海口/湖库：3000m-10000m。
3. 对支流交汇、入海口、水库口扩大 AOI。
4. AOI 需要保留上下游一定长度，避免切片过窄。

影像选择顺序：

1. Sentinel-2 L2A：优先用于无云时期的水体和岸线分析。
2. Sentinel-1 SAR：用于多云、雨季、洪水、夜间不受光照影响的水体判断。
3. Landsat：用于多年历史变化和枯丰水期对比。
4. GF-2/SkySat/Maxar：用于重点区域、小河流、电塔/桥梁/钓位级细节。

影像筛选条件：

1. 日期范围：优先最近 3-12 个月。
2. 云量：Sentinel-2 建议小于 20%-30%。
3. 季节：至少选枯水期和丰水期各一组。
4. 水位匹配：如果有水文站数据，记录影像日期对应水位。
5. 质量：剔除云、阴影、雪、强浑浊异常影像。

阶段产出：

- 河段 AOI 表。
- 遥感影像索引表。
- 影像质量评分。
- 每个河段的候选影像列表。

### 8.8 第 7 步：遥感提取水体和河段结构

目标：

- 将遥感影像转成可计算的河段特征。

光学影像处理：

1. 云掩膜。
2. 阴影掩膜。
3. 计算 NDWI、MNDWI、AWEI。
4. 根据区域自适应阈值提取水体。
5. 使用连通域过滤去掉小噪点。
6. 用河段 AOI 限制水体范围。
7. 矢量化水体边界。

SAR 影像处理：

1. 选择 Sentinel-1 IW 模式。
2. 选择 VV 或 VV+VH。
3. 做 speckle 去噪。
4. 做地形校正或使用 GEE 预处理结果。
5. 按区域阈值或分类器提取水体。
6. 与光学水体结果融合。

河段结构特征：

1. 河宽：
   - 沿中心线每隔固定距离生成横断线。
   - 与水体边界相交，计算宽度。
   - 输出平均宽度、最大宽度、最小宽度、宽度变化率。
2. 弯曲度：
   - 计算河段中心线长度与端点直线距离比例。
   - 输出 `sinuosity`。
3. 支流交汇：
   - 使用河网 graph 度数大于 2 的节点识别。
   - 统计上游支流数量。
4. 滩地/沙洲：
   - 多期水体边界之间的裸露区域。
   - 枯水期露出、丰水期淹没的区域。
5. 岸线变化：
   - 对比多期水体边界。
   - 输出变化面积和变化方向。
6. 入海口/潮汐影响：
   - 结合海岸线、潮汐站和水面变化。
7. 水库/湖泊影响：
   - 识别河流进入/流出水库或湖泊的位置。

阶段产出：

- 河段水体 mask。
- 河段水面矢量。
- 河宽统计表。
- 河段地形结构特征表。
- 低置信度遥感结果列表。

### 8.9 第 8 步：用遥感结果纠偏 OSM 路径

目标：

- OSM 提供路径候选，遥感提供当前水面事实。
- 最终生成可用于分析的河段中心线和水面范围。

纠偏步骤：

1. 将 OSM 河流线和遥感水体 mask 叠加。
2. 判断 OSM 线是否落在水体内或水体附近。
3. 若 OSM 线偏移但水体连续，使用水体中心线替换或修正。
4. 若 OSM 线存在但遥感无水体：
   - 检查是否为季节性河流。
   - 检查是否被云影遮挡。
   - 检查是否为地下涵洞或城市暗渠。
   - 标记为低置信度。
5. 若遥感有水体但 OSM 无线：
   - 生成候选新河段。
   - 用天地图、POI、人工审核判断是否加入河网。
6. 若 OSM 和天地图有冲突：
   - 遥感优先用于几何。
   - 官方/POI/人工结果优先用于名称。

输出字段：

- `geometry_source`：OSM、remote_sensing、official、manual。
- `geometry_confidence`。
- `geometry_update_time`。
- `needs_review`。
- `review_reason`。

阶段产出：

- 更新后的河段中心线。
- 更新后的水面边界。
- 几何偏移报告。
- 遥感补全河段列表。

### 8.10 第 9 步：生成河段信息画像

目标：

- 为钓鱼适宜性评分提供结构化特征。

静态特征：

1. 河流名称。
2. 河段长度。
3. 河段等级：主河道/支流/沟渠/水库口/入海口。
4. 平均河宽。
5. 河宽变化。
6. 弯曲度。
7. 支流交汇数量。
8. 距离桥梁、闸坝、道路、居民地、停车点。
9. 岸坡坡度。
10. 滩地/沙洲面积。
11. 岸线变化强度。
12. 是否季节性水流。
13. 是否处于禁钓区、保护区、饮用水源保护区。

动态特征：

1. 当前天气。
2. 未来 24 小时降雨。
3. 风速风向。
4. 气压变化。
5. 当前水位。
6. 水位涨落趋势。
7. 流量变化。
8. 入海口潮汐阶段。
9. 近期暴雨或洪水风险。

模型/VLM 辅助描述：

1. 对高分影像或遥感切片生成自然语言描述。
2. 描述内容包括河道宽窄、弯道、浅滩、岸线可达性、障碍物候选。
3. VLM 输出必须绑定影像切片和置信度。
4. VLM 不能直接作为经纬度几何数据来源。

阶段产出：

- `river_segment_profile` 表。
- 河段结构描述。
- 钓点评分输入特征。

### 8.11 第 10 步：钓鱼适宜性评分

目标：

- 根据河段结构和实时环境输出可解释评分。

MVP 规则：

1. 基础地形分：
   - 支流交汇加分。
   - 弯道外侧或回水区加分。
   - 河宽变化明显加分。
   - 滩地/沙洲附近加分。
2. 水文分：
   - 水位稳定加分。
   - 水位短时暴涨扣分。
   - 流速过快扣分。
   - 入海口按潮汐窗口加权。
3. 天气分：
   - 大风、雷暴、强降雨扣分。
   - 气压剧烈变化扣分。
   - 温度极端扣分。
4. 安全合规分：
   - 禁钓区直接过滤。
   - 高压线、电塔、危险岸坡强提示或过滤。
   - 洪水预警、雷电预警直接扣分。
5. 置信度：
   - 数据源越完整，评分置信度越高。
   - 缺少水位、遥感低质量、名称冲突时降低置信度。

输出结果：

- `score`：0-100。
- `score_level`：不建议、一般、适合、较优。
- `confidence`：低、中、高。
- `positive_reasons`：推荐原因。
- `negative_reasons`：风险原因。
- `data_missing`：缺失数据说明。

阶段产出：

- 河段评分 API。
- 推荐原因解释。
- 风险提示。

### 8.12 第 11 步：人工审核和反馈闭环

目标：

- 防止 OSM 缺失、瓦片误判、遥感误检、名称冲突导致错误上线。

需要进入人工审核的情况：

1. 名称置信度低于 0.5。
2. 几何置信度低于 0.6。
3. OSM、天地图、遥感三者明显冲突。
4. 支流交汇处名称无法判断。
5. 遥感水体被云、阴影、城市高反射干扰。
6. 系统识别到疑似禁钓区或危险区域。
7. 用户举报河名错误、路径错误、钓点不可达。

审核动作：

1. 修改河段名称。
2. 调整河段中心线。
3. 合并或拆分河段。
4. 标记季节性河流。
5. 标记禁钓、危险、不可达。
6. 上传现场照片或用户反馈。
7. 确认遥感补全河段是否有效。

反馈数据：

- 用户鱼获。
- 用户到达和停留。
- 收藏、分享、导航。
- 现场水位和照片。
- 禁钓举报。
- 河名纠错。
- 安全风险反馈。

阶段产出：

- 审核后台。
- 审核日志。
- 用户反馈表。
- 训练样本和规则调整依据。

### 8.13 第 12 步：上线数据更新机制

目标：

- 保持 OSM、遥感、天气、水位和用户反馈持续更新。

更新频率建议：

1. OSM 数据：
   - MVP：每月更新一次。
   - 正式上线：每周或每日增量更新。
2. Sentinel-2：
   - 每 5-10 天扫描一次样区。
   - 云量过高时延后。
3. Sentinel-1：
   - 雨季、洪水期提高频率。
4. 高分影像：
   - 重点河段季度或按需更新。
5. 天气：
   - 实况 15-60 分钟更新。
   - 预报 1-6 小时更新。
6. 水位/流量：
   - 根据 API 能力，1-6 小时更新。
7. 潮汐：
   - 每日更新未来 7-10 天。
8. 用户反馈：
   - 实时入库，审核后生效。

更新流程：

1. 拉取新数据。
2. 写入 raw 表。
3. 运行差异检测。
4. 只重算变化影响的河段。
5. 更新置信度和版本号。
6. 生成变更报告。
7. 高风险变更进入人工审核。
8. 审核通过后发布到线上。

版本管理：

- 每个河段保留 `version`。
- 几何、名称、评分规则、实时特征分别记录版本。
- 支持回滚。
- 支持追溯某次推荐使用的数据版本。

## 9. 技术架构

### 数据层

- PostGIS：存储河流矢量、河段、遥感提取边界、站点、POI、禁钓区。
- Object Storage：存储遥感切片、模型输入输出、质检样本。
- 时序库或 Redis：存储天气、水位、潮汐实时数据。
- 元数据表：记录数据来源、时间、分辨率、授权、置信度。
- OSM 原始表：存储 OSM PBF 导入后的水系线、水面和完整 tags。
- 名称候选表：存储 OSM、天地图、POI、人工审核得到的河名候选。
- 河网 graph 表：存储 node、edge、上下游关系和流向置信度。

### 离线处理层

- GIS 处理：河流裁切、拓扑修复、河段切分、上下游关系构建。
- 遥感处理：云掩膜、水体指数、SAR 水体分类、矢量化。
- 模型处理：水体分割、地物检测、电塔候选识别、VLM 图像描述。
- 质检处理：抽样审核、置信度评分、异常河段标记。
- OSM 处理：PBF 下载、标签过滤、入库、更新、ODbL 署名和派生数据管理。
- 命名处理：多源名称匹配、名称传播、名称冲突检测。

### 在线服务层

- 河段查询 API。
- 钓点适宜性评分 API。
- 实时天气/水位聚合 API。
- 地图瓦片或矢量瓦片服务，用于展示和审核，不用于批量反向提取。
- 管理后台和人工审核后台。

### 评分模型

MVP 推荐先用规则模型：

- 地形结构：35%
- 水位/流量/潮汐：25%
- 天气：20%
- 季节/时段：10%
- 安全/合规：10%

示例规则：

- 水位短时暴涨：扣分。
- 强降雨、雷暴、大风：扣分。
- 支流交汇、弯道、缓流回水区：加分。
- 入海口涨退潮窗口：按目标鱼种和潮汐阶段加权。
- 电线、高压线、禁钓区、危险岸坡：强风险提示或直接过滤。

后续模型化：

- 收集用户反馈、鱼获、停留时长、收藏、导航到达、举报等数据。
- 使用 Learning-to-Rank 或 GBDT/XGBoost 做评分校准。
- 保留可解释规则，避免黑箱推荐。

## 10. 上线阶段

### 阶段 0：样区验证，1-2 周

目标：

- 选 1 个流域或 2-3 条目标河流。
- 下载并裁切 OSM PBF，抽取水系线、水面和名称。
- 下载 1:25万水系矢量作为官方对照。
- 配置天地图底图用于后台人工校验。
- 拉取 Sentinel-2、Sentinel-1、Landsat 影像。
- 接入一个天气 API 和一个水文/潮汐 API。

详细任务：

1. 确定样区 AOI。
2. 下载 `china-latest.osm.pbf` 或按 AOI 裁切 PBF。
3. 过滤 OSM 水系标签。
4. 建立 OSM 原始表和水系候选表。
5. 下载目标图幅 1:25万水系数据。
6. 建立 OSM 与天地图水系匹配关系。
7. 建立初版河网 node/edge。
8. 生成基础河段。
9. 用 OSM name 和天地图自然地名做河名候选。
10. 对每个河段生成 AOI buffer。
11. 拉取 Sentinel-2 和 Sentinel-1 影像。
12. 生成第一版水体 mask。
13. 输出河宽、弯曲度、支流交汇等基础特征。
14. 做 20-50 个河段人工抽检。

产出：

- 样区河段库。
- OSM 水系入库脚本。
- 河网 graph 原型。
- 河名候选和置信度。
- 河宽、水面、岸线变化样例。

## 11. 日常应用补充功能落地方案

当前河段分析、遥感结构识别、天气/水位/潮汐评分落地后，可以覆盖“找河段、看环境、判断是否适合钓”的基础日常需求。要形成真正高频可用的日常产品，还需要补齐两类功能：

1. 可达性 + 安全合规功能。
2. 用户反馈 + 鱼获闭环功能。

这两个功能都可以落地，而且应当进入 MVP 或 MVP 后的第一轮增强。

### 11.1 功能一：可达性 + 安全合规

#### 是否可落地

可以落地，建议作为 MVP 的必备功能之一。

原因：

- 用户日常使用时不仅关心“这个河段鱼情是否可能好”，还关心“能不能到、能不能钓、安不安全”。
- 河段评分如果缺少可达性和合规判断，会出现推荐了禁钓区、危险岸坡、无法停车、无法下到水边等问题。
- 可达性和安全合规数据不需要完全依赖遥感模型，很多可以通过地图 POI、道路、官方公告、天气预警和人工审核实现。

#### 覆盖的具体功能点

1. 到达能力：
   - 距离最近道路。
   - 距离最近停车点。
   - 步行到水边距离。
   - 是否有桥梁、堤坝、码头、亲水平台、河边小路。
   - 车辆是否可以接近。
2. 安全风险：
   - 高压线、电线塔、电线跨河。
   - 陡坡、悬崖、深水岸线。
   - 泄洪口、闸坝、水库出水口。
   - 雷暴、大风、强降雨、洪水预警。
   - 夜间不可达或危险区域。
3. 合规风险：
   - 禁钓区。
   - 禁渔期。
   - 饮用水源保护区。
   - 自然保护区、湿地保护区。
   - 水库、河道、城市公园的地方管理规则。
4. 用户体验：
   - 显示“推荐去/谨慎去/不建议去”。
   - 给出原因，例如“距离道路 80m、无禁钓记录、今日无雷暴预警”。
   - 给出风险，例如“疑似高压线附近”“水位上涨较快”“可能处于保护区边界”。

#### 数据来源

可达性数据：

- OSM 道路、桥梁、路径、停车点：
  - `highway=*`
  - `bridge=yes`
  - `amenity=parking`
  - `footway`
  - `track`
  - `path`
- 高德、百度、腾讯位置服务：
  - POI 检索。
  - 路线规划。
  - 逆地理编码。
  - 周边道路和停车点。
- 天地图底图：
  - 后台人工审核参考。
- 高分影像：
  - 核验河边道路、平台、堤岸、建筑、桥梁。

安全数据：

- 高分影像或人工标注识别电塔、电线、闸坝、危险岸线。
- OSM 电力设施标签：
  - `power=line`
  - `power=tower`
  - `power=pole`
- 天气预警 API：
  - 雷暴。
  - 大风。
  - 暴雨。
  - 高温。
  - 寒潮。
- 水文数据：
  - 水位上涨。
  - 超警戒水位。
  - 流量异常。

合规数据：

- 地方农业农村局、渔政部门发布的禁渔期、禁钓区公告。
- 水利局、生态环境局、自然资源部门公开的水源保护区、自然保护区、湿地保护区数据。
- 河长制公示数据。
- 城市公园、水库、景区、管理处公告。
- 用户举报和人工审核补充。

#### 落地步骤

第 1 步：建立可达性数据表。

建议表：

- `access_road`：道路和小路。
- `access_parking`：停车点。
- `access_entry_point`：可下水或可到岸边入口。
- `access_bridge`：桥梁。
- `access_poi`：码头、平台、公园、村口、堤坝等。

字段：

- `id`
- `source`
- `source_id`
- `name`
- `type`
- `geometry`
- `distance_to_segment`
- `confidence`
- `updated_at`

第 2 步：计算河段可达性。

对每个河段计算：

1. 最近道路距离。
2. 最近停车点距离。
3. 最近桥梁距离。
4. 最近人行路径距离。
5. 是否存在 200m、500m、1000m 内入口。
6. 从道路到河边是否有明显路径。
7. 是否处于封闭区域、工厂、铁路、高速、保护区内部。

输出字段：

- `access_score`
- `nearest_road_distance`
- `nearest_parking_distance`
- `nearest_entry_distance`
- `walk_distance_estimate`
- `access_level`
- `access_reasons`

第 3 步：建立安全风险图层。

建议表：

- `risk_power_facility`：高压线、电塔、电杆。
- `risk_hydraulic_facility`：闸坝、泄洪口、水库出水口。
- `risk_terrain`：陡坡、危险岸线。
- `risk_weather_alert`：天气预警。
- `risk_water_alert`：水位/流量预警。

第 4 步：建立合规规则库。

建议表：

- `regulation_area`：禁钓区、保护区、水源地。
- `regulation_period`：禁渔期、季节限制。
- `regulation_notice`：公告原文、来源链接、发布时间。
- `regulation_rule`：结构化规则。

字段：

- `area_name`
- `rule_type`
- `geometry`
- `start_date`
- `end_date`
- `allowed`
- `source_url`
- `source_department`
- `confidence`
- `review_status`

第 5 步：接入评分系统。

评分规则：

- 禁钓区：直接不推荐。
- 饮用水源一级保护区：直接不推荐。
- 雷暴/暴雨/洪水预警：直接不推荐或强风险提示。
- 距离停车点过远、无道路可达：降低推荐。
- 疑似高压线附近：降低推荐并提示风险。
- 有道路、停车点、合法可钓、无预警：提升可用性评分。

第 6 步：前端展示。

河段详情页增加：

- “可达性”：好/一般/困难。
- “安全风险”：无明显风险/谨慎/不建议。
- “合规状态”：可钓/未知/疑似限制/禁钓。
- “到达建议”：最近停车点、步行距离、附近入口。
- “风险说明”：高压线、涨水、禁钓、雷暴等。

#### MVP 做法

MVP 阶段不需要做到完全自动化。

建议先做：

1. OSM 道路和停车点距离计算。
2. 商业地图 POI 查询附近停车、道路、桥梁。
3. 天气预警和水位预警接入。
4. 人工维护禁钓区和危险区域。
5. 后台人工审核重点河段。

MVP 输出：

- `access_score`
- `safety_score`
- `legal_status`
- `risk_tags`
- `access_reasons`

#### 后续增强

1. 用高分影像识别真实小路、平台、堤岸。
2. 用用户轨迹验证实际可达路径。
3. 用用户举报补充封路、禁钓、危险区域。
4. 与地方水利、渔政、保护区数据合作。
5. 引入电塔/高压线检测模型。

### 11.2 功能二：用户反馈 + 鱼获闭环

#### 是否可落地

可以落地，而且是后期最重要的数据壁垒。

原因：

- 遥感、水文、天气只能判断环境是否适合，不能直接知道鱼是否开口。
- 用户真实鱼获、空军、鱼种、饵料、水深、水色、时间段，是校准推荐模型的核心数据。
- 没有反馈闭环，评分长期只能停留在规则模型；有反馈闭环后，可以逐步训练区域化、季节化、鱼种化模型。

#### 覆盖的具体功能点

1. 用户鱼获记录：
   - 鱼种。
   - 数量。
   - 重量。
   - 照片。
   - 时间。
   - 钓法。
   - 饵料。
   - 水深。
   - 水色。
   - 是否走水。
2. 空军/有口反馈：
   - 有口无鱼。
   - 完全无口。
   - 小鱼闹窝。
   - 水流过急。
   - 水位变化大。
3. 钓点状态：
   - 可达。
   - 封路。
   - 禁钓。
   - 人多。
   - 垃圾多。
   - 危险。
4. 纠错反馈：
   - 河名错误。
   - 河段路径错误。
   - 水位异常。
   - 禁钓信息错误。
   - POI 错误。
5. 推荐效果反馈：
   - 推荐准确。
   - 不准确。
   - 原因不符合现场。

#### 落地步骤

第 1 步：先做轻量反馈入口。

河段详情页增加按钮：

- “我钓到了”
- “空军了”
- “这里禁钓”
- “这里危险”
- “位置/河名不对”
- “现场水情不对”

第 2 步：设计最小表单。

MVP 不要让用户填太多字段。

“我钓到了”表单：

1. 鱼种。
2. 数量或重量。
3. 照片，可选。
4. 钓法/饵料，可选。
5. 是否公开，可选。

“空军了”表单：

1. 有无鱼口。
2. 水流情况。
3. 水色。
4. 人多不多。
5. 备注，可选。

“风险/禁钓”表单：

1. 类型：禁钓、危险、封路、高压线、涨水、垃圾、其他。
2. 照片，可选。
3. 位置，可选。
4. 备注。

第 3 步：做审核机制。

需要审核的内容：

- 禁钓举报。
- 危险举报。
- 河名纠错。
- 地图路径纠错。
- 高影响鱼获，例如大鱼、热门点位。
- 带照片的公开内容。

审核结果：

- 通过。
- 驳回。
- 需要更多证据。
- 标记为低置信度。

第 4 步：把反馈转成模型特征。

聚合维度：

1. 河段。
2. 时间段。
3. 季节。
4. 天气。
5. 水位趋势。
6. 鱼种。
7. 钓法。

生成指标：

- 近 7 天鱼获次数。
- 近 7 天空军比例。
- 近 30 天有效反馈数。
- 某鱼种活跃度。
- 用户反馈置信度。
- 推荐命中率。
- 风险举报数量。

第 5 步：回写评分系统。

规则：

- 最近有效鱼获多：适当加分。
- 最近空军比例高：适当降分。
- 最近禁钓/危险举报多：强降分或进入审核。
- 反馈少：不改变基础评分，只降低置信度。
- 反馈集中在少数用户：降低权重，防刷。

第 6 步：建立反作弊和隐私保护。

反作弊：

- 同一用户短时间重复提交限流。
- GPS 与河段距离过远降低置信度。
- 照片 EXIF、时间、位置可辅助校验，但不能强依赖。
- 异常大鱼或营销内容进入审核。
- 新用户反馈权重较低，可信用户权重较高。

隐私：

- 用户可选择隐藏精确位置。
- 对外展示只展示河段级，不默认展示精确钓点。
- 鱼获照片需支持删除。
- 用户轨迹和位置需要明确授权。
- 热门小钓点可做模糊化，避免过度曝光。

#### MVP 做法

MVP 阶段建议只做三类反馈：

1. 鱼获反馈。
2. 空军/有口反馈。
3. 禁钓/危险纠错。

MVP 不做复杂社区，不做排行榜，不做公开精确钓点。

MVP 输出：

- 河段近 7 天/30 天反馈概况。
- 用户反馈标签。
- 推荐评分的反馈修正项。
- 后台审核队列。

#### 后续增强

1. 针对鱼种做推荐，例如鲫鱼、鲤鱼、翘嘴、鲈鱼。
2. 训练区域化推荐模型。
3. 建立可信用户等级。
4. 做鱼获热力但模糊化展示。
5. 结合饵料、钓法、时间窗口给建议。
6. 引入现场照片 VLM 分析水色、浑浊度、岸线环境。

## 12. 合规和风险

地图合规：

- 使用公开地图或矢量数据对外展示时，应遵守《地图管理条例》和公开地图审图要求。
- 涉及中国境内地图展示时，要注意审图号、坐标系、敏感地物和边界表达。

坐标系：

- 官方基础地理数据通常使用 CGCS2000。
- 商业地图常使用 GCJ-02 或 BD-09。
- 遥感影像通常为 WGS84 或投影坐标。
- 系统内部必须统一坐标基准，并记录数据来源坐标系。

电力设施：

- 电线塔、电线、高压线等设施可能涉及安全敏感信息。
- 对外展示不建议提供过高精度的设施坐标。
- MVP 中建议只作为“垂钓安全风险提示”，不作为公开电力设施地图。

钓鱼合规：

- 需要接入禁钓区、保护区、饮用水源保护区、自然保护区、地方禁渔期等规则。
- 推荐结果必须提示用户遵守当地法规。

数据授权：

- 免费数据不代表可以任意商用、缓存、二次分发。
- 商业影像和商业地图数据必须明确授权范围。
- 用户上传鱼获、位置、轨迹、照片需要隐私政策和授权。
- OSM 数据使用需遵守 ODbL 协议，保留署名，并评估派生数据库的开放义务。
- OSM 官方瓦片不能批量抓取或离线缓存。
- 天地图瓦片应按授权在线调用，不建议批量下载和反向提取。

## 13. 推荐的数据精度策略

第一阶段：

- 使用 OSM PBF 作为河流路径和名称候选主数据。
- 使用 1:25万水系矢量作为官方水系对照，不作为高精几何。
- 使用天地图瓦片作为后台在线校验底图，不批量抓取。
- 使用 Sentinel-2/Sentinel-1 更新水面范围和纠偏 OSM 几何。
- 使用 Landsat 做历史变化。
- 输出中大型河流和部分 OSM 覆盖较好的小河流河段级推荐。

第二阶段：

- 对重点河段采购或申请 GF-2、SkySat、Maxar、吉林一号等高分影像。
- 重新提取河岸线和钓点附近结构。
- 对电塔/电线做候选识别和人工审核。
- 补全 OSM 缺失或遥感低置信度的小河流。

第三阶段：

- 申请 1:5万、1:1万或更高比例尺官方基础测绘成果。
- 与地方水利、自然资源、商业地图和自采数据融合。
- 建立自有高精河段数据库。

最终原则：

> OSM 解决“可批量获取的河流路径和名称候选”；天地图和官方数据解决“官方对照和人工校验”；遥感解决“河现在准确在哪里、河段结构如何”；水文、天气、潮汐和用户反馈解决“现在适不适合钓”。
